## 原始需求复述

在不破坏现有零权限 SAF 架构的前提下，完成三项增量：

1. **T6**：增强手机端预览列表（`MainActivity` + `ui/ApkAdapter.kt`）的交互能力，让用户能够**逐项掌控**重命名，而不是只能"全量执行"。
2. **T7**：为 Android TV 提供一套 leanback 适配界面，复用现有核心模块，D-pad 可完整操作。
3. **T8**：把 `compileSdk` / `targetSdk` 从 34 恢复为 35，并同步 README。

### 4.1 T6 · 列表交互增强

| ID | 优先级 | 需求 | 验收标准 |
|---|---|---|---|
| RQ-T6-1 | **P0** | 列表项支持多选：每项左侧 CheckBox，点击整行 = 切换选中 | 点击行与点击 CheckBox 行为一致；选中态有明显视觉反馈（勾选 + 行底色） |
| RQ-T6-2 | **P0** | 批量操作条：列表上方显示「已选 N / 共 M」+ 全选 / 反选 / 清空 | 计数实时准确；「全选」只作用于**当前筛选后的可见集合** |
| RQ-T6-3 | **P0** | 执行范围收敛为选中集合：`确认重命名` 只处理"选中 ∧ `needsRename` ∧ `meta.isValid`"的项 | 确认弹窗文案显示真实条数；未选中的文件磁盘上不发生任何变化 |
| RQ-T6-4 | **P0** | 选中态以 `documentId` 为键独立存储，不因 `applyRule()` 重算列表而丢失 | 在设置页改规则返回后，原有勾选保持；重命名成功的项自动移出选中集合 |
| RQ-T6-5 | **P0** | 长按弹出上下文菜单：复制原名 / 复制目标名 / 排除此项 / 查看详情 | 长按不触发选中切换；菜单项在不可用时置灰（如无目标名时"复制目标名"不可用） |
| RQ-T6-6 | P1 | 「查看详情」弹窗展示完整元数据（应用名、包名、versionName/Code、min/targetSdk、大小、修改时间、相对路径、元数据来源、失败原因） | 解析失败项也能打开，显示 `meta.error` |
| RQ-T6-7 | P1 | 单项目标名**就地编辑**：弹出输入框预填目标名，保存后仅覆盖该项 | ①输入必须经 `NameComposer` 的清洗与 `ConflictGuard` 校验，**禁止在 UI 层另写清洗逻辑**；②与同目录其它文件冲突时给出内联错误且不允许保存；③编辑结果标记为"手动"，重新「生成预览」时**不被规则覆盖**，重新「扫描」后允许丢失 |
| RQ-T6-8 | P1 | 状态筛选 Chips：全部 / 待改名 / 无需改 / 已完成 / 失败，附各自计数 | 切换即时生效；筛选不改变选中集合内容，只改变可见性 |
| RQ-T6-9 | P1 | 排序菜单：文件名 / 大小 / 修改时间 / 状态，可切升降序 | 排序稳定；排序后选中态、滚动位置行为可预期 |
| RQ-T6-10 | P1 | 会话内状态记忆：选中集合、筛选条件、排序方式在 `onResume()` 与横竖屏切换后保留 | 从设置页返回、旋转屏幕后三者均不重置（进程被杀后可丢失） |
| RQ-T6-11 | P1 | 空态与结果态提示优化：目录未选 / 扫描为空 / 筛选后为空，三种空态文案不同 | 三种场景文案互不相同且可指导下一步操作 |
| RQ-T6-12 | P2 | 搜索框：按文件名或包名实时过滤（与状态筛选取交集） | 输入防抖 ≥200ms，1000 条列表输入不卡顿 |
| RQ-T6-13 | P2 | 滑动手势：左滑 = 排除该项，右滑 = 仅重命名该项（右滑需二次确认） | 与多选/长按无冲突；**若与 RQ-T6-1 交互冲突则本项直接砍掉**，不做妥协式实现 |
| RQ-T6-14 | P2 | 列表项显示应用图标（从已解析元数据获取，无则占位角标） | 不得为取图标而新增权限或第三方库；不得拖慢滚动（复用现有缓存策略） |

**T6 性能与质量约束**

- 选中态刷新必须走 **DiffUtil payload 局部刷新**，禁止 `notifyDataSetChanged()`；1000 条列表下全选/反选无可感知卡顿（帧耗时 ≤16ms）。
- 选中态**不得污染领域模型**：优先使用 UI 层行模型或适配器持有的 `Set<String>`，`model/ApkItem.kt` 是否新增字段由架构师定夺（见待确认问题 Q1）。
- RQ-T6-7 涉及的名称清洗/冲突校验能力若需从 `NameComposer` 暴露新的公开入口，**必须补 JVM 单测**，且 `NameComposer` 保持零 Android 依赖。

## 五、UI 设计说明

### 5.1 T6 · 手机端主界面（`activity_main.xml` 增量）

**改动定位**：在现有「Toolbar → 目录卡片 → 进度条 → 状态文本 → RecyclerView → 底部按钮条」结构中，
于**状态文本与 RecyclerView 之间**插入「筛选/排序条」与「批量操作条」两层，其余结构保持不变。

```
┌──────────────────────────────────────────────┐
│ ApkRenamer                      [⚙] [🗑]     │  ← 现有 MaterialToolbar（不变）
├──────────────────────────────────────────────┤
│ ┌ 目录卡片 ──────────────────────────────┐  │  ← 现有（不变）
```

**交互细则**

| 手势 / 操作 | 行为 |
|---|---|
| 单击行任意位置 | 切换该项选中态（等价于点 CheckBox） |
| 长按行 | 弹出上下文菜单（复制原名 / 复制目标名 / 排除此项 / 编辑目标名 / 查看详情） |
| 点击筛选 Chip | 切换可见集合，**不改变**选中集合 |
| 点击 ⇅ | 弹出排序菜单（文件名 / 大小 / 修改时间 / 状态 + 升降序） |
| 「全选」 | 只作用于当前筛选后的可见项 |
| 执行按钮 | 文案随选中数动态变化；选中数为 0 时置灰 |

**状态与文案**

| 场景 | 文案 |
|---|---|
| 未选目录 | 「尚未选择文件夹，点击上方『选择文件夹』开始」 |
| 扫描结果为空 | 「该目录下没有 apk / apkm / apks / xapk 文件」（沿用现有） |
| 筛选后为空 | 「当前筛选条件下没有文件，试试切换到『全部』」 |
| 选中数为 0 时点执行 | 「请先勾选需要重命名的文件」 |

**默认行为（与现有产品的兼容性设计）**

生成预览后，**默认自动勾选所有 `needsRename` 的项**。这样用户"选目录 → 扫描 → 执行"的既有心智路径不变（仍是一键全量），
多选只是在此基础上提供"取消勾选以排除"的能力，避免老用户升级后发现"点执行没反应"。
